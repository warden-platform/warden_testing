# 项目定位与四层分工

## 定位

独立于 warden 主仓库的**黑盒 API / 业务流验收测试仓库**，技术栈 `pytest + requests + allure`。

- warden 主仓库负责 Go 单元 / 组件 / DB 门控集成测试（500+）。
- 本仓库负责从外部 HTTP 视角验证：API 契约、跨层业务流、安全边界、发布前回归。
- 不依赖真实 Kubernetes / Jenkins / 网络设备，内置 Python 版测试 Connector。

## 四层

| 层 | 职责 | 禁止 |
|---|------|------|
| `case/` | 测试场景编排，只调用 `lib/` 与 fixture | 裸 `requests`、请求细节、断言实现 |
| `lib/` | 控制面 API 封装、测试 Connector、数据工厂 | 把业务判断塞进工具层 |
| `tools/` | HTTP、断言、轮询、签名、唯一 ID、日志等基础能力 | 依赖具体业务接口 |
| `config/` | 环境与凭据加载 | 把地址/密钥硬编码进代码 |

新增或修改用例时，先把请求细节、数据库/凭据、日志、断言归到对应层，不要散落到 `case/`。
